DATA SOURCE: PLACSP (national platform), Atom/CODICE XML
- Monthly zip: https://contrataciondelsectorpublico.gob.es/sindicacion/
  sindicacion_643/licitacionesPerfilesContratanteCompleto3_YYYYMM.zip
  (~160-300 MB, ~2 h each). Live: ...Completo3.atom (~500 entries/page,
  rel="next" links use the old domain contrataciondelestado.es -> rewritten).
- One <entry> = one VERSION of a tender; keep the newest `updated` per id.
  Tombstones = at:deleted-entry.
- XML has: buyer + NIF, budget, CPVs, deadline, NUTS, criteria + weights,
  solvency requirements, PDF links (PCAP = LegalDocumentReference,
  PPT = TechnicalDocumentReference), results (winner NIF, bid count,
  lowest/highest bid, award amount, per lot).
- IT filter (CPV prefixes): core 72*, 48*; hardware 302*; telecom 3242*, 6421*.
- Status codes: PUB open, EV evaluation, ADJ awarded, RES resolved,
  PRE prior notice, ANUL cancelled.
- Downloaded: raw/placsp_202606..202609.zip + raw/live/. Not in git.

PIPELINE (data-pipeline/)
- placsp_fetch.py   month YYYYMM | live --pages N | docs [--open-only] [--ids a,b]
- placsp_parse.py   streaming parser -> dict per tender (+ criteria, documents,
                    results, requirements, lots); latest_versions(); it_segment()
- build_dataset.py  <zips/atoms...> --segments all -> out/tenders.jsonl, *.csv,
                    stats.md. region_of() maps NUTS2 -> autonomous community.
- load_supabase.py  reads out/tenders.jsonl + out/extractions/*.json; batched
                    upsert (200/commit), newer-wins on `updated`; replaces child
                    rows; refreshes buyer_stats. 8.7k tenders take ~16 s.
- extract_tender.py SCHEMA (frontend contract) + verify(). Citations are
                    {doc, page, quote, verified}. doc = PDF stem ("pcap__...",
                    "ppt__...") or "placsp_xml" (checked against tenders.jsonl).
                    API mode: claude-opus-5-5, structured output, fallbacks
                    (unused: no key).
- schema.sql        tenders, tender_criteria, tender_documents, tender_results,
                    tender_requirements, tender_extractions (+ RLS: authenticated
                    read).
- backend.sql       companies (owner RLS + demo company), tender_decisions,
                    buyer_stats (materialized view), upcoming_renewals (view),
                    match_tenders(company uuid, limit) fit score. Re-runnable.
- API.md            how the Next.js app calls everything (supabase-js).
- .github/workflows/daily-ingest.yml (repo root): live 3 pages -> build -> load;
                    needs the DATABASE_URL secret (not set yet).
- Rebuild everything:
    python3 build_dataset.py raw/placsp_2026{06,07,08,09}.zip raw/live --segments all
    uv run -q --python 3.13 --with "psycopg[binary]" load_supabase.py

GOTCHAS LEARNED
- Some PDFs draw checkboxes and tables as IMAGES: text extraction reads every
  checkbox as "SI" and misses score tables. Check page images (render with
  pymupdf get_pixmap and view), or cite placsp_xml.
- PDF text: use pymupdf, write raw/text/<id>__<label>.txt with
  "=== PAGE n ===" markers; quotes must be verbatim from the cited page (±1).
- The first 8 normalised words of a quote are what verify() matches; avoid
  hyphenated line breaks in quotes.
- Discount stats: per-lot budget, competitive procedures only, n >= 3, else noise.
- Testing RLS on Supabase: `set local role authenticated` +
  set_config('request.jwt.claims','{"sub":"<uuid>","role":"authenticated"}',true).
  Locally: stub auth.uid() reading current_setting('test.uid').
